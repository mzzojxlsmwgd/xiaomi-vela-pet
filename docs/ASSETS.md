# 素材制作规范

框架对素材**几乎不设限** —— 尺寸、比例、格式都能自适应。这一页说明哪些是真的要遵守、
哪些随便，以及怎么做体积才不会失控。

---

## 一句话版本

> 任意尺寸、任意比例、透明底 PNG，命名 `<名字>_<帧号>.png` 丢进 `src/common/emoji/`，
> 再到 `config/emoji.js` 的 `EMOJI` 里加个名字。想有动画就多放几帧。

---

## 尺寸

**不用管。** 页面里所有 `<image>` 都用了 `object-fit: contain`：

- 等比缩放到容器内，**不变形**
- 不裁切、不留边
- 原图多大都行，正方形 / 竖长 / 横宽通吃

只需要注意**清晰度**：按显示尺寸的 1.5 倍以上给。

| 设备 | 表情显示边长（设计 px） | 建议原图边长 |
|---|---|---|
| 小米手环 10 | 178 | ≥ 260 px |
| 小米手环 10 Pro | 146 | ≥ 220 px |
| 红米手表 4 | 201 | ≥ 300 px |
| 红米手表 5 / 6 | 235 | ≥ 350 px |

框架自带的占位图是 **208×208**，刚好覆盖到红米手表 5/6 的 235（略小一点，
但简笔画本身不讲究锐度）。换成真实美术素材建议给到 320~400。

---

## 底色

**透明底**（alpha 通道）。原因：表情叠在纯黑 + 毛玻璃的底上，白底图会露出一个方块边框。

如果素材本身是白底（比如从视频里截的），可以：
1. 抠图成透明，或
2. 把底色改成和 `theme.js` 里 `bg` 一样的黑 —— 但毛玻璃层会让它露出一点边界，不如抠图干净。

---

## 格式

默认 **PNG**。想用 JPG / WEBP 就改 `config/emoji.js`：

```js
export const EXT = 'webp'
```

⚠️ 这是**全局后缀**，改完所有表情都得是同一个格式。
JPG 不支持透明底，一般不建议用在表情上。

---

## 帧数（动画是可选项）

### 静态图（推荐先这么做）

只放一张：

```
src/common/emoji/happy_0.png
```

`FRAMES` 里什么都不用写 —— **默认就是 1 帧**，不会尝试加载不存在的 `_1.png`。

### 多帧动画

按帧号连续命名，从 0 开始：

```
src/common/emoji/sing_0.png
src/common/emoji/sing_1.png
src/common/emoji/sing_2.png
```

然后登记帧数：

```js
const FRAMES = {
  sing: 3
}
```

主页会按 `FRAME_TICKS`（每 2 个 tick ≈ 120ms）换一帧，循环播放。

**注意**：
- 帧数**必须和实际文件数一致**。写多了会请求不存在的图（空白）；写少了多余的帧永远不播
- 帧数建议 ≤ 12。再多会让 `setInterval` 的负担变重，且手环上肉眼也分不出
- 循环要**首尾能接上**，否则会看到一跳

## 体积

框架自带的 12 张占位图一共 **48 KB**，整个包 **124 KB**。

真实素材的经验值：单张 208px 透明 PNG 量化到 24 色大约 3~5 KB；
一套 10 帧 ≈ 40 KB；12 套 ≈ 500 KB。手环存储完全吃得下。

> 网上流传的「快应用不能超过 300KB」是 GIF 时代的社区经验值，
> 从没被官方证实过。实际红线取决于设备存储，手环类设备通常有几 MB 可用。

**压缩建议**：用 `pngquant` 或 PIL 的 `quantize(colors=24)`。
项目里的 `tools/gen_placeholder_emoji.py` 就是这么做的，可以照着改。

---

## 命名

- 全小写、英文、无空格（`happy` / `shy` / `surprise`）
- 名字会变成文件名和 `EXPR_LINES` 的 key，**别用中文**
- 必须有一个叫 `idle` 的 —— 它是兜底表情

---

## 加一套表情的完整流程

```bash
# 1. 放图
cp my_sad_*.png src/common/emoji/

# 2. 改 config/emoji.js
#    EMOJI 数组里加 'sad'；有动画就在 FRAMES 里登记帧数

# 3. （可选）加专属台词
#    config/dialogue.js 的 EXPR_LINES 里加 sad: ['……']

# 4. （可选）让情绪关键词能命中它
#    config/mood.js 的 RULES 里加 { k: ['难过','失落'], e: ['sad'] }

# 5. 编译看效果
npm run build
```

第 3、4 步可以省 —— 缺 `EXPR_LINES.sad` 会回落到 `EXPR_LINES.idle`，
缺 mood 规则只是这条台词不会主动切到这个表情。

## 应用图标

`src/common/img/icon.png`，`manifest.json` 里引用。要求 **192×192、正圆、四角透明**。

> **必须是正圆**，不要用圆角矩形。手表桌面的图标位是圆形遮罩，方角那部分会被切掉，
> 看起来就像图标被啃了一口。框架自带的图标（`tools/gen_icons.py` 生成）就是按正圆画的：
> 圆形底 96 半径，最外圈装饰环收到 75，留 21% 边距。

换图标最简单的方式：直接覆盖这个文件（框架自带的是和占位表情同款的简笔画笑脸）。
想重新生成就跑 `python tools/gen_icons.py`。
